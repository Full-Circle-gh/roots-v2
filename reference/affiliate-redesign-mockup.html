What every option removes: the five-paragraph explainer (now one sub-line), the # id column, the manual Refresh button, the separate "Rewarded" date column (folded into each row's one-line story), and the "turn it on in Settings → Features" detour — the switch lives on the page it controls.

What every option adds: the deal restated as one human sentence (so the merchant reads what customers are actually promised), a real WeChat share-card preview with the auto-added ¥ and code (instead of a bare image box), a conversion read (96 of 128 ordered), and status names that say what they mean — Waiting / Rewarded / Voided instead of JOINED / ORDERED / VOID.

A — ledger first (§7 one screen, one question): the page's question is "is the program bringing orders?" so referrals lead and the stats double as the filter — no duplicate summary strip. The deal sits aside, sticky, always visible while scrolling the ledger; the same shell as Flash sales, so Marketing feels like one family.

B — the deal is a sentence: settings stop looking like a form. Five numbers live inside the promise itself, edited in place; below the fold the page is pure activity. The boldest of the three — quietest to read, least conventional to build.

C — two rooms: configure and monitor are different errands, so they get different rooms. Activity opens with the three numbers that say whether the program works; Settings is a calm one-column form you visit twice a year. Most conventional, most familiar.

The Dusk budget (§1): one Dusk element per option — the breathing dot beside "Running", because a referral program is the shop working by itself. Sage is spent only on "reward paid", amber only on "waiting", brick only on Void. Nothing is decorated.
