What moves, and what happens to the bottom bar

  • Print receipt goes into the pinned action row, pushed to the right edge so it holds one position on every order. It stops being a hunt at the bottom of a long panel.
  • The bottom bar disappears. It only ever held Print receipt, Box label, the failed-print pill and the "Prints at Tianhe" hint. With print at the top there is nothing left worth a whole bar, and the panel gets those 61px back. The bar already collapses when empty, so this needs no new plumbing.
  • "Prints at Tianhe" becomes the button's tooltip. It answers a question you ask once — which counter does this come out of — so it belongs on hover, not parked on screen forever.
  • Box label (only on when Settings · Delivery turns it on) and any Undo dispatch / Undo preparing move into the ⋯ menu at the end of the row. That caps the row at four visible controls, which is what keeps the pinned height fixed.
  • A failed print moves to the marks line under the header, in brick with the printer's own error on hover — still above the fold, where the operator is already looking.

Why C drops the timestamp out of the pinned block

The rulebook (§1.13a) is blunt about this: a pinned region is a fixed height regardless of content, and the pinned header carries one pill — the record's primary status. Extra marks go in the body below it. That rule exists because an earlier attempt at this same header let three pills wrap to a second row, and the "fixed" header doubled in height on exactly the messy orders where staying put matters most. Frame C obeys it by keeping the pinned block to two rows that cannot grow, and giving the marks their own line just below.

The placed time follows the same logic. It is read once, on arrival, and the Ship-by card repeats it further down. Keeping it pinned costs 21px of every screen for a line nobody looks at twice.

Build notes

  • The pinned block must be the panel's top edge, not a band laid over it — it takes the drawer's own paper ground (--bg-app), fully opaque, and draws no corner of its own.
  • Pin with position: sticky; top: 0 on .order-head inside #order-detail-mount, plus negative side margins so the band is full-bleed. Set the mount's top padding to 0 — a sticky child pins to the padding edge, so 20px of padding leaves a gap for the ¥total banner to peek through. The phone layout already does exactly this; desktop copies it.
  • z-index: 4 — above the rows, below the floating ✕ at 5. Any higher and the header paints over the close button, which is a sibling of the scroll body rather than inside it.
  • Check every ancestor for an overflow in either axis before shipping. overflow in one axis computes the other to auto, which turns that element into the scrollport and parks the header on row one instead of the panel top.
  • The hairline + soft shadow appear only once content has scrolled under the band (the stuck class here). At rest there is no line, so an unscrolled order looks exactly as it does today.
  • The marks line joins its parts with a styled separator element, never a " · " text node — the live translator treats space-middot-space as an English/中文 pair and would split it.
