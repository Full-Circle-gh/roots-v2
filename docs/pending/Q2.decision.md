## §NEW — WHERE MONEY GOES IS CHANGED ONLY WITH THE PAYMENTS PERMISSION

**Built 2026-10-01 under §412.2** (Ash: *"as you recommend fix all"*).
Tax, the display currency, the manual-Alipay record and the WeChat Pay merchant
details now need `settings:payments`; the owner always passes. Ash's own call,
overriding §325.3 for these writes only, it deliberately takes them away from
the keys that held them: the other Settings keys (`settings:shop`,
`settings:push`, `stores:view`, `shipping:config`, `delivery:view`), the setup
pair, and `integrations:manage`. Every screen hides the controls from anyone
the server would now refuse, so nobody is refused after a tap.

1. **The server.**
   - **`PUT /config`:** `currency` and `tax.*` need `settings:payments`
     (`lib/cap-routes.js` CONFIG_FAMILIES, `configKeyCap`).
   - **`PUT /alipay-manual`:** needs `settings:payments` (`requiredCapFor`).
   - **`POST /channel-hub/miniapp/wechat-pay-verify`:** needs
     `settings:payments`. It saves and checks only WeChat Pay fields.
   - **`POST /channel-hub/miniapp/wechat-creds`, split by field:** the choke
     point admits either key, and the handler checks each field before
     anything is written (`wechatCredsFieldCap`):
     - the login pair (`appId`, `appSecret`) needs `integrations:manage`;
     - the WeChat Pay details (`mchId`, `serialNo`, `apiV3Key`, `privateKey`,
       `platformPubKey`) need `settings:payments`.

     A field counts only when the save would **change** it: a secret that was
     typed, or a plain value (AppID, merchant ID, certificate serial) that
     differs from the stored one. The configuration page sends all seven
     fields pre-filled, so this lets either key save its own half without
     tripping on the other's unchanged values. If one save mixes a permitted
     change with a refused one, it is refused whole and writes nothing. The
     env-managed account (Roots) writes nothing here, so it is never refused.
   - **Not changed:** the rest of `/channel-hub` stays `integrations:manage`.
2. **The desktop.**
   - **The Currency, Tax and manual-Alipay cards** carry
     `data-cap="settings:payments"`, so they are hidden without the key. The
     shared "Save settings" bar no longer sends the hidden Alipay card
     (`saveAlipayManualInline`).
   - **The setup guide's payment step** has no button without the key
     (`suGoPayment` guards too). Its chooser writes the currency and the
     Alipay record.
   - **The Mini App configuration page** draws each half editable, and sends
     it, only for its own key. Without either key there is no Save. The setup
     guide re-entry button needs `integrations:manage`.
   - **The Mini App wizard** opens only at a step the account may save. After
     step 1, without the payments key, it ends on the configuration page
     instead of the merchant-account step.
3. **The phone.**
   - **Payments** (currency, tax, Alipay) and its two doors are
     `settings:payments` alone (`ROUTE_CAP.paycfg`, `PAY_KEYS`). They still
     fail closed while the keys load.
   - **The WeChat Mini App screen** follows the desktop: each half editable,
     and sent, for its own key. The payments key is `mCanKnown`, so it fails
     closed while loading. The pay steps of the wizard, and the finish page's
     shortcuts to them, exist only for that key.
4. **Who loses what.** These lose these writes on purpose:
   - an admin or manager without `settings:payments`;
   - a shop-floor account holding a Settings key;
   - an integrations manager.

   The admin and manager presets do include `settings:payments` (they hold
   every key but `billing:pay`, `team:permissions`, `stores:delete` and
   `integrations:signin`), so in practice it is custom roles and the narrower
   presets that lose them.
5. **Tests.**
   - New `scripts/test_wechat_creds_field_gates.js`: the real router on a
     self-serve tenant, each half both ways, unchanged pre-filled values,
     a mixed save refused whole, the owner, and the desktop's hiding.
   - Updated to assert the narrower rule both ways:
     `test_settings_write_gates.js`, `test_last_open_writes.js`,
     `test_mobile_payments_settings.js`, `test_mobile_wechat_miniapp.js`
     and `test_alipay_manual_unread_save.js`.
